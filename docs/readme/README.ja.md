# Jiumi 揪咪

アプリが前面とバックグラウンドで何をしているかを確かめ、残すか、制限するか、無効化やアンインストールをするかを決められます。
<br>Root もパソコンも不要で、記録はスマートフォン内に保存されます。

## 機能

### アクティビティを把握する

| 機能 | できること |
| --- | --- |
| アクティビティの概要 | **今回のセッション、今日、7 日間、30 日間**の合計、推移、平均、ピーク、バックグラウンドの回数を確認できます。曲線をタップまたはスライドすると各時間帯を読めます。監視も記録もない期間には No records と表示されます。 |
| 注意が必要 | **ヒートマップ**で目立つ日や時間帯を見つけ、バックグラウンドでのデータ送信と機密性の高いアクティビティ、繰り返しの読み取り、拒否後の繰り返しの試行を確認できます。 |
| アプリ別ランキング | すべて、またはバックグラウンドのアクセス数で活発なアプリを見つけ、アクセスしたデータを比較できます。システムの定常処理は別に折りたたまれます。 |
| アプリの詳細 | 同じ曲線で 1 つのアプリの推移を確認できます。データの種類をタップすると、曲線とタイムラインにその種類だけが表示されます。 |
| アクティビティ記録 | 位置情報、クリップボード、デバイス識別子などを含む **12 グループ・56 種類のアクセス** を閲覧できます。記録は時間、アプリ、種類ごとに表示でき、バックグラウンドのアクティビティで絞り込むこともできます。 |
| ネットワークアクティビティ | アプリごとに接続先アドレスと利用可能な通信量の測定値を確認できます。ドメイン記録を有効にすると、対応付けられた接続にドメインを表示できます。 |
| システム履歴 | アプリの詳細を開くと、Android が保持している権限アクセス記録と合計回数を確認できます。モニタリング開始前の一部のアクティビティも含まれます。 |

### モニタリングと記録

| 機能 | できること |
| --- | --- |
| モニタリングの除外リスト | Settings › Monitoring › Monitoring allowlist で監視しないアプリを選べます。新しい記録は作られず、保存済みの記録は一時的に非表示になります。リストから外すと再表示されますが、除外中のアクティビティは補完されません。 |
| 通知 | モニタリング中は、経過時間と停止ボタンを表示する通知が表示されます。Settings › Notifications でオフにできます。Show summary をオンにすると、**セッションのアクセス数とバックグラウンドの回数**がアプリ名なしで表示されます。Attention alerts をオンにすると、新たに注意が必要な項目が発生したときに、セッション内でアプリと項目ごとに 1 回通知されます。 |
| ログのエクスポート | Settings › Logs › Export logs で、選択した期間の記録を CSV ファイルを含む ZIP として保存できます。 |

## アプリの管理

アプリはインストール元ごとにまとめられています。アプリの詳細を開いてアクティビティを確認し、変更するかどうかを判断できます。アプリの管理操作はすべてユーザーが開始します。変更のたびに、Jiumi は Android から状態を読み戻して反映されたかを確認し、Android が拒否した場合はその理由を表示します。

<p align="center">
  <a href="../images/app-disable.en.png"><img src="../images/app-disable.en.png" width="250" alt="アプリの無効化を確認する画面を示すウェブサイトのデモ" /></a>&nbsp;
  <a href="../images/app-delete.en.png"><img src="../images/app-delete.en.png" width="250" alt="アンインストールの確認とバックアップの案内を示すウェブサイトのデモ" /></a>&nbsp;
  <a href="../images/app-restore.en.png"><img src="../images/app-restore.en.png" width="250" alt="アンインストールしたアプリの復元とバックアップを破棄する操作を示すウェブサイトのデモ" /></a>
</p>

| 操作 | 内容 |
| --- | --- |
| 権限 | アプリの詳細の Permissions で、権限を 1 つずつオフまたはオンにできます。Manageable permissions を使うとすべてを一度にオフにでき、再びオンにすると Jiumi がオフにした権限だけが元に戻ります。システムがロックしている権限は読み取り専用として表示されます。 |
| ネットワークアクセス | 対応デバイスでは、VPN スロットを使わずに Android 標準のファイアウォールで個々のアプリのネットワークアクセスをブロックまたは復元できます。アプリが他のアプリと UID を共有している場合、ルールが別のツールによって設定されている場合、または Jiumi がこのアプリだけに影響することを確認できない場合は、スイッチが理由とともにロックされます。 |
| アプリの無効化・有効化 | Android が現在のユーザーに対してアプリを無効にします。アプリとデータは保持されます。Apps › Disabled から再度有効にできます。無効になったアプリには雪の結晶のバッジが付きます。 |
| 再度有効化 | Jiumi が無効にしたアプリが再び有効になっているのを検出すると、一覧と詳細に Re-enabled と表示されます。タイムラインには検出日時が記録されます。Settings › App management › Disable again when re-enabled をオンにすると、Jiumi が再びアプリを無効にします。 |
| 自分でインストールしたアプリのアンインストール | 確認のため完全なパッケージ名を入力します。Jiumi は基本 APK と分割 APK（ある場合）をバックアップします。Apps › Uninstalled から再インストールを試みることができます。**アンインストールするとアプリのデータは削除されます。バックアップにはインストールファイルだけが保存されます。** |
| プリインストールアプリのアンインストール | Settings › App management で Allow uninstalling preinstalled apps をオンにすると、対応するプリインストールアプリを現在のユーザーに対してアンインストールできます。出荷時のコピーとアプリのデータは保持されます。Apps › Uninstalled から復元を試みることができます。アンインストールしたアプリにはゴミ箱のバッジが付きます。オフの状態で Uninstall をタップすると、説明が表示され App management に移動できます。 |

Settings › App management の Runs as には、これらの操作を誰が実行するかが表示されます。Root、または Root で起動した Shizuku を使う場合、アプリの無効化と有効化、およびプリインストールアプリのアンインストールと復元は Root として実行されるため、スマートフォンが shell による変更を許可していないシステムアプリも Jiumi で変更できます。ワイヤレスデバッグまたはネットワークデバッグを使う場合は shell として実行され、スマートフォンは一部のシステムアプリの変更を許可しません。その場合 Jiumi は理由を表示します。自分でインストールしたアプリのアンインストールは現在のユーザーにのみ影響するため、仕事用プロファイルやセカンドスペースにあるコピーは保持されます。

コアシステムコンポーネントはデフォルトで保護されています。スマートフォンが依存しているコンポーネントを変更すると、システム機能に影響する場合があります。Jiumi はそのような変更の前に警告を表示します。

## Jiumi は Root なしでどのようにバックグラウンドのアクティビティを把握するのですか？

Android は、アプリの実行に伴って権限アクセス記録、接続テーブル、システムトレース、イベントログを提供しています。Jiumi のモニターは、利用可能なシステムシグナルを **shell ユーザー** として読み取ります。アプリはそれらをルールに従って整理し、スマートフォン内のデータベースに保存します。モニタリングによって他のアプリにコードが注入されることはありません。アプリの無効化やアンインストール、権限やネットワークアクセスのオフといった操作は、アプリの管理でユーザー自身が開始する必要があります。

<p align="center"><img src="../images/how-it-works.en.png" alt="アプリが Android のシステムシグナルを生成します。Jiumi のモニターがそれらを shell ユーザーとして読み取り、アプリが記録を整理してスマートフォン内に保存します。オプションのドメイン記録では、ローカル VPN を通じて DNS クエリを受け取ります。" width="900" /></p>

| シグナル源 | Jiumi が把握できること |
| --- | --- |
| 権限アクセス記録 (AppOps) | どのアプリがいつ権限を使用したか、および Android が保持している履歴。 |
| 接続テーブル | アプリがどのアドレスに接続したか。デフォルトでは 5 秒ごとにサンプリングされます。 |
| システムトレース (Perfetto) | 識別可能なシステムサービスの呼び出しと、システムが対応している場合は接続ごとの通信量。 |
| イベントログ | プロセスがいつ起動したか、および Android が記録した理由。 |

### 4 つの接続方法

| 方法 | 向いている人 | 初回設定 | 再起動後 |
| --- | --- | --- | --- |
| **ワイヤレスデバッグ**（推奨） | ほとんどのスマートフォン。Root とパソコンは不要 | Wi-Fi に接続し、端末上でペアリングコードを一度入力 | ペアリングは保持。Wi-Fi とワイヤレスデバッグをオンにする必要あり |
| **ネットワークデバッグ** | ADB ポートが開いている端末 | ポートを検索または入力し、必要に応じて Android で許可。ペアリングコードは不要 | 端末がポートを再び開く必要あり |
| **Shizuku** | Shizuku を使用中の人 | Shizuku を起動して Jiumi を許可 | Shizuku が動作している必要あり |
| **Root** | Root 化済みの端末 | Root マネージャーで Jiumi を許可 | 許可が有効な間は利用可能 |

4 つの方法すべてでモニターは shell ユーザーとして動作します。Root、または Root で起動した Shizuku の場合に限り、上記のアプリ管理操作が Root として実行されます。

> **ネットワークデバッグの安全上の注意：** Jiumi は端末自身のアドレスにのみ接続し、ポートを開くことはありません。ただし `adb tcpip` などで開いたポートは、通常、同じネットワーク上の他の端末からもアクセスできます。信頼できるネットワークでのみ使用し、心当たりのないデバッグ要求は許可せず、不要なときはポートを閉じてください。

**オプションのドメイン記録** は、ローカル VPN を使って DNS クエリを受け取り、現在のネットワークの DNS サーバーへそのまま転送します。その他の通信は宛先へ直接送られます。ドメイン記録はシステムの VPN スロットを占有します。また、アプリ独自の暗号化 DNS や、ホスト名を指定したプライベート DNS プロバイダを使うクエリは、ドメイン記録を経由しない場合があります。

## ダウンロードしてモニタリングを開始する

1. Android 11 以降の ARM64 スマートフォンで、[GitHub Releases](https://github.com/ybblab/Jiumi/releases/latest) から APK をダウンロードしてインストールします。
2. Jiumi を初めて開いたときに起動方法を選択します。推奨されるワイヤレスデバッグの場合は、Wi-Fi に接続し、セットアップに従って通知を許可し、開発者向けオプションをオンにして、Jiumi の通知にシステムの 6 桁のペアリングコードを入力します。通知から入力できない場合は、ステップ 3 で “Can’t type in the notification?” をタップし、分割画面、小さいウィンドウ、またはクイック設定タイルからコードを入力します。ADB ポートがすでに開いている場合は、ネットワークデバッグも選べます。
3. Monitor ページで Start monitoring をタップします。モニタリング中は常駐通知が表示されます。モニタリングは通知またはアプリから停止できます。

<p align="center">
  <a href="../images/pairing-split.en.png"><img src="../images/pairing-split.en.png" width="196" alt="その他のペアリング方法：分割画面または小さいウィンドウ" /></a>&nbsp;
  <a href="../images/pairing-tile.en.png"><img src="../images/pairing-tile.en.png" width="196" alt="その他のペアリング方法：クイック設定タイル" /></a>
</p>

スマートフォンの再起動、Jiumi のアップデート、デバッグサービスの中断のあと、選択した接続が利用可能であれば Jiumi は同じセッションの再開を試みます。アプリに戻ったときにも再試行します。カードに Monitoring interrupted と表示された場合は、接続を復旧してから Resume をタップします。中断していた時間はモニタリング時間に含まれません。

ネットワークデバッグでモニターが停止すると、Jiumi は前回のポートを試すか、ローカルポートを再検索してセッションの再開を試みます。ポートが見つからない場合や許可が必要な場合はカードに表示されます。

ワイヤレスデバッグを使用する場合、USB デバッグも併せてオンにしておくと、Wi-Fi の切断時に Android がワイヤレスデバッグをオフにしても、実行中のモニターを維持しやすくなります。Settings › Connection › Backup connection はデフォルトでオフで、端末内に限定された ADB ポートをシステムがすでに提供している場合にのみ使えます。Jiumi はそのポートを検証して再利用し、新しいポートは開きません。詳しくは [セットアップガイド](https://jiumi.ybblab.com/en/download/) をご覧ください。

## プライバシーと制限事項

- **記録はスマートフォン内に保存されます。** Jiumi にはアカウントがなく、モニタリングの記録をアップロードしません。アプリは GitHub でアップデートを確認できます。アップデートを選択すると APK をダウンロードし、そのサイズ、SHA-256、署名を検証します。アップデートの確認はオフにできます。
- **記録が示すのはアクティビティと接続です。** Jiumi は権限が使用されたことやアクセスが拒否されたことを表示できます。メッセージ、パスワード、ネットワーク通信の内容は見ることができません。
- **把握できる範囲はシステムに依存します。** 短い接続はサンプリングの合間に終了することがあり、ファイルの直接読み取りなどの操作では利用可能なシグナルが生じない場合があります。接続ごとの通信量には Android 14 以降とシステムの対応が必要です。Jiumi は誤報を減らすため、確認できない一部のアクティビティを除外します。
- **概要とランキングでは集計方法が異なります。** 概要には Android が時間帯ごとに保持する回数が補われ、監視開始前の時間が含まれることがあります。ランキングは Jiumi の個別記録のみを数えます。セッションが 31 日を超えると、Session の概要と通知は最初の 31 日のみを集計します。その場合は 30 days を使用してください。
- **モニタリングは追加のバッテリーを消費します。** 消費量はアプリのアクティビティによって異なります。不要になったら通知からモニタリングを停止してください。

## ソースからビルドする

JDK 17 と Android SDK が必要です。

```sh
cd code
./gradlew :app:assembleDebug
```

モニタリングのカテゴリ、注意ルール、保護対象のアプリは [rules ディレクトリ](../../code/app/src/main/assets/rules/) で設定されています。コードの構成と貢献の手順については [CONTRIBUTING.md](../../CONTRIBUTING.md) をご覧ください。
